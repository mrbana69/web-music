Product Requirements Document (PRD): Preluded V2 – Spotify & YouTube Music Bridge1. Executive SummaryObiettivo: Riprogettare l'infrastruttura backend e lo streaming della PWA "Preluded", eliminando la dipendenza dai mirror pirata di Tidal (ecosistema hifi-api / Monochrome) e implementando un'architettura ibrida legale e sostenibile.Concetto Core: L'app utilizzerà le API ufficiali di Spotify per la gestione della libreria, dei metadati e delle playlist, e fungerà da "ponte" verso YouTube Music per la risoluzione e lo streaming audio gratuito in background, il tutto gestito tramite Vercel Serverless Functions per aggirare i blocchi CORS del browser.2. Architettura di SistemaComponenteStack TecnologicoScopoFrontend (PWA)HTML/JS o React/Next.jsUI, player audio HTML5/MediaSession, gestione stato locale (token).Backend ProxyVercel Serverless (Python/Node)Risoluzione stream, astrazione API, bypass CORS.Libreria (Sorgente)Spotify Web APIGestione utente, recupero playlist, metadati brani (titolo, artista, durata).Motore Audioytmusicapi / yt-dlpRicerca del brano su YT Music, estrazione URL audio diretto (opus/m4a).Database/CacheVercel KV o SQLite in memoriaCaching della mappatura Spotify_ID ➔ YouTube_Video_ID.3. Cosa Sostituire e Rimuovere dal Codice AttualeRimuovere i Mirror Illegittimi:Eliminare completamente l'array API_ENDPOINTS (es. [https://hifi.geeked.wtf](https://hifi.geeked.wtf), monochrome.tf, qqdl.site) da index.html e dai file di configurazione.Sostituire la Logica di Fetch Audio:Rimpiazzare le vecchie chiamate di rete che puntavano a /track/:id sui mirror Tidal con chiamate interne alla propria infrastruttura Vercel: /api/stream?title=X&artist=Y.Aggiornare il Gestore di Autenticazione:Sostituire (se presente) l'inserimento di token Tidal con un modulo UI di doppio login (Spotify + Google/YouTube).4. Gestione Autenticazione (Dual Login)A. Spotify (Gestione Libreria)Flusso: OAuth 2.0 PKCE (Proof Key for Code Exchange).Implementazione Frontend:Generazione di code_verifier e code_challenge in locale.Redirect a [accounts.spotify.com/authorize](https://accounts.spotify.com/authorize) con gli scope: user-read-private, playlist-read-private, user-library-read.Callback gestita dal client per scambiare il codice con un access_token e un refresh_token, salvandoli in localStorage.B. YouTube Music (Streaming & Cronologia)Flusso: OAuth Device Code Flow (TV Flow).Implementazione Backend (Vercel Python):Endpoint /api/yt/get-code: Inizializza OAuthCredentials().get_code() da ytmusicapi e restituisce al client un codice univoco a 8 lettere e l'URL di Google Device.Endpoint /api/yt/verify-code: Controlla in polling se l'utente ha autorizzato il codice; restituisce il token JSON definitivo.Il frontend salva questo token JSON criptato in localStorage e lo allega (via header) ad ogni richiesta successiva verso il backend Vercel per firmare le ricerche e le estrazioni audio.5. Logica del "Ponte" (Resolver)Il cuore del sistema è la Serverless Function /api/resolve ospitata su Vercel.Flusso Operativo:Input: Riceve dal frontend title, artist e duration_ms (presi da Spotify).Cache Check: Controlla se la combinazione Spotify_ID è già mappata a un Video_ID di YouTube nel database (KV/Redis).Ricerca (Fallback): Se non in cache, istanzia ytmusicapi (con il token dell'utente) e cerca: "{title} {artist}".Fuzzy Matching:Estrae i primi 5 risultati filtrati per songs.Calcola uno score usando rapidfuzz sui campi di testo.Applica una penalità se la durata differisce di oltre $\pm 7$ secondi rispetto a duration_ms.Output: Restituisce al frontend il videoId vincitore.6. Motore di Riproduzione (Playback)Per mantenere il player UI nativo di Preluded (controlli volume, seek bar, MediaSession API in background su smartphone):Estrazione Stream:Una Serverless Function /api/stream-url?videoId=XYZ utilizza sotto il cofano yt-dlp (o un porting equivalente come ytdl-core) per risolvere il videoId nell'URL diretto firmato da Google (formato audio/webm o audio/mp4).Iniezione nel Client:L'URL estratto viene iniettato nel tag esistente della PWA:JavaScriptconst audioPlayer = document.getElementById('main-audio-player');
audioPlayer.src = directGoogleCdnUrl;
audioPlayer.play();
Gestione Scadenza:Gli URL estratti scadono dopo ~6 ore. Se si tenta di fare seek o riprodurre un URL scaduto (errore 403 HTTP sul tag audio), il client deve intercettare l'errore onerror, chiamare nuovamente /api/stream-url e riprendere dal currentTime salvato.7. Roadmap di Sviluppo (MVP)Fase 1: Setup Infrastruttura VercelCreazione directory api/ nel repository.Setup ambiente Python per le funzioni serverless e installazione dipendenze (ytmusicapi, rapidfuzz, yt-dlp).Fase 2: Autenticazione Client-SideScrittura del modulo UI per il login Spotify (PKCE).Verifica caricamento corretto delle playlist nella UI.Fase 3: Il Resolver e StreamingSviluppo di /api/resolve per il matching dei metadati.Sviluppo di /api/stream-url per l'estrazione audio.Test di latenza tra click play (Spotify metadata) -> Resolver -> Estrazione -> Playback effettivo.Fase 4: Integrazione Autenticazione YouTube Music (Opzionale per MVP 1.0)Aggiunta del Device Code Flow per consentire agli utenti di ascoltare in alta qualità e senza blocchi bot, inviando le credenziali generate agli endpoint Vercel tramite Authorization headers.
